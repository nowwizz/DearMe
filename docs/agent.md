# Agent 설계

~~~mermaid
flowchart LR
  A[분석] -->|정보 충분| P[계획]
  A -->|인사·안내·되묻기| R[응답]
  P --> E[실행]
  E --> J[판단]
  J -->|충족·종료| R
  J -->|대안 필요| B[재계획]
  B --> E
~~~

| 노드 | 입력 → 출력 |
| --- | --- |
| 분석 | 요청·SQLite 최근 대화 → 변경 조건, 의도, 되물을 항목. LLM 구조화 호출 실패 시 규칙으로 추출. |
| 계획 | 완성된 기준 조건 → Tool 단계와 의존성. 실연동에서 LLM에 네 Tool 스키마를 주고 시작 Tool을 선택. |
| 실행 | 작업 계획 → TMAP 기준 역 좌표, 후보, ID 기반 상세, 장소 간 경로, 날씨 집계, 오류와 근거. 동일한 입력은 실행 중 재사용. |
| 판단 | 구간별·합산 보행 시간, 지역 반경, 제안 체류, 공개 운영·휴무, 식사 시간대와 사용자 조건 비교 → 충족·보류·제외. |
| 재계획 | 거리·순서와 후보를 바꾸거나 주변 후보·추가 페이지를 확인합니다. 기본 상한은 3회이며, 확보한 적합 코스는 더 나은 후보를 찾는 동안 유지합니다. |
| 응답 | 판정과 근거 → 편지, 타임라인, 지도, 준비 가이드, 노래 링크 또는 확인할 조건과 실패 안내. |

종료 예정 시각은 시작 시각에 보행, 제안 체류, 시간대에 맞추는 대기, 5분 여유를 더해 계산합니다. 확인된 한 구간이 30분을 넘으면 후보에서 제외합니다. 종료 제한을 넘으면 가능한 시작 시각을 역산하고 휴일 운영을 해석할 수 없으면 확인 필요로 표시합니다. 역은 검색의 기준점이며 별도 출발지가 없으면 첫 방문지부터 일정을 계산합니다. 예산 입력은 판단에 사용할 수 있고, 전체 비용을 확인할 수 없으면 충족 판정을 보류합니다.

SQLite Memory는 사용자 조건, 최근 요청·응답, 최근 초대장 제목을 보관합니다. 후속 요청은 추출된 필드만 변경합니다. 실연동과 시연 모드는 별도 세션을 사용합니다.

실연동에서는 요청 분석과 시작 Tool 선택에 GMS를 사용합니다. 제약 판정과 재계획 상한은 실제 Tool 응답과 규칙으로 계산합니다. 시연은 제공된 고정 데이터와 규칙을 사용해 동일한 입력을 재현할 수 있습니다.

실행 이벤트 발행부는 화면 폴링 버퍼와 별도 LoggingAgent에 단계 시작·종료, Tool 요청·완료 및 소요 시간, 의도·선택 이유, 판단, 재계획, 종료를 전달합니다. LoggingAgent는 검증된 이벤트만 SQLite에 추가합니다. 발행 데이터에서 사용자 발화·인증값·원본 API 응답·오류 전문은 제외합니다. 관찰자별 실패는 서로 격리되어 기록 저장을 끄거나 저장 오류가 발생해도 대화가 계속됩니다.
