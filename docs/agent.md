# Agent 설계

~~~mermaid
flowchart LR
  A[분석] -->|정보 충분| P[계획]
  A -->|인사·안내·되묻기| R[응답]
  P --> E[실행]
  E --> J[판단]
  J -->|충족·종료| R
  J -->|대안 필요| B[재계획]
  B --> E
~~~

| 노드 | 입력 → 출력 |
| --- | --- |
| 분석 | 요청·SQLite 최근 대화 → 변경 조건, 의도, 되물을 항목. LLM 구조화 호출 실패 시 규칙으로 추출. |
| 계획 | 완성된 기준 조건 → Tool 단계와 의존성. 실연동에서 LLM에 네 Tool 스키마를 주고 시작 Tool을 선택. |
| 실행 | 작업 계획 → 후보, ID 기반 상세, 장소 간 경로, 날씨 집계, 오류와 근거. 동일한 입력은 실행 중 재사용. |
| 판단 | 분류, 합산 보행 초, 제안 체류, 공개 운영·휴무·입장료와 사용자 조건 비교 → 충족·보류·제외. |
| 재계획 | 제외된 순서 → 거리와 순서를 바꾼 대안, 필요 시 주변 조회나 추가 페이지. 기본 3회. 치명적 인증·사용 한도 오류는 즉시 정리. |
| 응답 | 판정과 근거 → 편지, 타임라인, 지도, 준비 가이드, 비용과 노래 링크 또는 실패 안내. |

종료 예정 시각은 시작 시각에 경로 소요 초, 제안 체류, 5분 여유를 더합니다. 종료 제한을 넘으면 가능한 가장 늦은 시작 시각을 역산합니다. 특별 운영을 해석할 수 없으면 확인 필요로 표시합니다. 출발지가 명시되지 않으면 첫 장소를 시작점으로 제안하고 첫 장소까지 이동 제외를 표시합니다. 총예산과 1인 예산을 구분하고, 전체 비용을 확인할 수 없으면 예산 충족 판정을 보류합니다.

SQLite Memory는 사용자 조건, 최근 요청·응답, 최근 초대장 제목을 보관합니다. 후속 요청은 추출된 필드만 변경합니다. 실연동과 시연 모드는 별도 세션을 사용합니다.

실행 이벤트 발행부는 화면 폴링 버퍼와 별도 LoggingAgent에 단계 시작·종료, Tool 요청·완료 및 소요 시간, 의도·선택 이유, 판단, 재계획, 종료를 전달합니다. LoggingAgent는 검증된 이벤트만 SQLite에 추가합니다. 발행 데이터에서 사용자 발화·인증값·원본 API 응답·오류 전문은 제외합니다. 관찰자별 실패는 서로 격리되어 기록 저장을 끄거나 저장 오류가 발생해도 대화가 계속됩니다.
